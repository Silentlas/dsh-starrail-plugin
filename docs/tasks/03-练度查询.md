# T3 · 练度查询（mihomo 数据接入）

> 负责人：**B** ｜ 前置：T1 ｜ 工期：2 天
> 本模块**不需要任何 Cookie**，只要 UID。这是本插件相对同类产品的核心优势，别把凭证依赖加进来。

## 一、目标

用 UID 拉到玩家全部**公开展示**的角色数据，整理成结构化模型，提供文本查询，并为 T4（评分）、T6（AI 点评）提供统一的数据对象。

## 二、数据源（已实测）

```
GET https://api.mihomo.me/sr_info_parsed/{uid}?lang=chs
```

- 实测 UID 100041113 返回 200 / 172KB
- 顶层：`player` + `characters`
- `player`：`uid` `nickname` `level` `world_level` `signature` `space_info{memory_data, universe_level, avatar_count, light_cone_count, relic_count, achievement_count}`
- `characters[]`：`id` `name` `rarity` `rank`（命座）`level` `promotion` `path` `element` `skills` `skill_trees` `light_cone` `relics` `relic_sets` `statistics` `attributes` `additions` `properties`
- `relics[]`：`id` `name` `type`（1-6 部位）`set_id` `set_name` `rarity` `level` `main_affix{field,name,value,display,percent}` `sub_affix[]`（同上结构）
- `light_cone`：`id` `name` `rarity` `rank`（叠影）`level` `attributes` `properties`

**必须写进帮助文案的限制**：只能拿到玩家在米游社「角色展示」里放出来的角色（实测 129 个角色只解析出 8 个）。查不到时提示用户去米游社设置展示角色。

## 五、`model.py`（T4/T6 都按这个写）

```python
"""练度数据的结构化模型：外部 API 字段 → 内部统一对象"""
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class Affix:
    """一条词条（主词条或副词条）"""
    field: str          # hp / atk / crit_rate / speed ...
    name: str           # 中文名
    value: float
    display: str        # 已格式化的展示串，如 "54.6%"
    percent: bool

@dataclass
class Relic:
    slot: int                   # 1-6：头/手/躯/脚/位面球/连结绳
    name: str
    set_id: str
    set_name: str
    rarity: int
    level: int
    main_affix: Optional[Affix]
    sub_affix: list[Affix] = field(default_factory=list)

@dataclass
class LightCone:
    name: str
    rarity: int
    rank: int           # 叠影
    level: int
    attributes: list[Affix] = field(default_factory=list)

@dataclass
class Character:
    id: str
    name: str
    rarity: int
    rank: int           # 命座
    level: int
    promotion: int
    path: str           # 命途：毁灭/存护/巡猎/丰饶/智识/同谐/虚无/记忆
    element: str        # 物理/火/冰/雷/风/量子/虚数
    attributes: list[Affix] = field(default_factory=list)   # 面板基础属性
    additions: list[Affix] = field(default_factory=list)    # 加成（含暴击率/暴伤/元素增伤）
    light_cone: Optional[LightCone] = None
    relics: list[Relic] = field(default_factory=list)
    relic_sets: list[str] = field(default_factory=list)     # 如 ["哀歌覆国的诗人×4"]
    skill_levels: dict[str, int] = field(default_factory=dict)  # 行迹等级 {"basic":1,"skill":10,...}

@dataclass
class Profile:
    uid: str
    nickname: str
    level: int
    world_level: int
    signature: str
    avatar_count: int
    light_cone_count: int
    relic_count: int
    achievement_count: int
    characters: list[Character] = field(default_factory=list)

    def find(self, keyword: str) -> Optional[Character]:
        """按名字模糊查找（支持别名映射后续再加）"""
```

实现要点：

- 缓存落 SQLite（在 `core/utils/store.py` 里新增，**由 D 负责的表不要碰**，自己加 `character_cache(uid TEXT PRIMARY KEY, payload TEXT, fetched_at INTEGER)`；如果 T5 也要加表，各自加各自的，命名不要冲突）

- 错误分类：`404/400` → 「UID 不存在或没有公开角色展示」；`429` → 「第三方接口限流，稍后再试」；超时/连接错误 → 「数据源暂时不可用」

## 十、风险

- mihomo.me 是第三方免费服务，可能限流或改结构。**必须**：缓存 + 明确的失败文案 + `model.parse_profile` 对缺字段做 `or 0` 兜底，不要让字段缺失变成 KeyError
- 别为了省事把 `mihomo` 的原始 JSON 直接回业务层，一定要转成 `model` 对象——T4/T6 依赖这个稳定契约
