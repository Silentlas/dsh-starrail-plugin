## 三、评分算法设计

### 3.1 有效词条权重表（`relic_weights.json`）

按**命途**分出通用权重，再按**元素**微调：

```json
{
  "version": 1,
  "paths": {
    "毁灭": {"atk_pct": 1.0, "crit_rate": 1.0, "crit_dmg": 1.0, "speed": 0.8, "dmg_boost": 1.0, "break_effect": 0.6, "hp_pct": 0.4, "def_pct": 0.3},
    "存护": {"def_pct": 1.0, "hp_pct": 1.0, "speed": 0.8, "effect_res": 0.7, "crit_rate": 0.3},
    "丰饶": {"hp_pct": 1.0, "speed": 1.0, "effect_res": 0.8, "outgoing_heal": 1.0},
    "同谐": {"speed": 1.0, "hp_pct": 0.7, "effect_res": 0.7, "def_pct": 0.6},
    "虚无": {"effect_hit": 1.0, "speed": 0.9, "atk_pct": 0.8, "crit_rate": 0.6, "break_effect": 0.6},
    "智识": {"atk_pct": 1.0, "crit_rate": 1.0, "crit_dmg": 1.0, "speed": 0.7, "dmg_boost": 1.0},
    "巡猎": {"crit_rate": 1.0, "crit_dmg": 1.0, "atk_pct": 1.0, "speed": 0.8},
    "记忆": {"atk_pct": 1.0, "crit_rate": 0.9, "crit_dmg": 0.9, "speed": 0.8, "dmg_boost": 1.0}
  },
  "elements": {
    "量子": {"dmg_boost": 1.0},
    "虚数": {"dmg_boost": 1.0}
  }
}
```

权重取值规则：`1.0` = 该角色核心属性；`0.7~0.9` = 有价值；`0.3~0.6` = 凑数；缺省 `0.0` = 完全无用。

**实现要求**：

- 权重表是**唯一可调的地方**，算法代码里不准出现针对某个角色的硬编码
- 表里查不到的命途，用「毁灭」兜底并在日志里 warn 一次（提示需要补表）
- 元素只影响 `dmg_boost` 是否算有效，不改变其他权重

### 3.2 单件遗器评分

```
单条副词条得分 = weight[field] × (value / 单次词条基准值)      # 归一化到「跳数」
单件得分       = Σ(副词条得分) / 部位满分 × 100              # 部位满分见下
有效副词条数   = 满足 weight[field] >= 0.7 的词条条数
```

基准值表（5★ 遗器单次成长的常见值，写进 `relic_weights.json` 的 `affix_step`）：

```json
"affix_step": {"atk_pct": 3.888, "hp_pct": 3.888, "def_pct": 4.86, "crit_rate": 2.916,
               "crit_dmg": 5.832, "speed": 2.3, "effect_hit": 3.456, "effect_res": 3.456,
               "break_effect": 5.832, "atk": 16.9, "hp": 33.8, "def": 16.9}
```

- 主词条不计分（部位固定，只有「主词条是否对」的判断，见 3.3）
- 部位满分（满分基准）：头/手 70，躯/脚 90，球/绳 90（可按实测数据校准，写常量并注明来源假设）

### 3.3 主词条匹配

按命途给出「推荐主词条」：

```python
RECOMMENDED_MAIN = {
    "躯": ["crit_rate", "crit_dmg", "atk_pct", "hp_pct", "def_pct", "outgoing_heal", "effect_hit"],
    "脚": ["speed", "atk_pct"],
}
```

判断：主词条命中推荐列表 → 记为「对」；否则记为「错」，并在诊断里点名。

### 3.4 套装匹配

`relic_sets` 从 T3 model 拿（形如 `"哀歌覆国的诗人×4"`）。本期只做**数量校验**：

- 4 件套：至少 4 件同套 → 有效；否则提示「缺少 4 件套，建议 2+2 或补满」
- 2+2：两套各 2 件 → 记为「可用」

不做套装效果数值计算（那需要套装表，属于伤害引擎范畴）。

## 四、面板总评（`panel.py`）

```python
"""面板总评与短板诊断"""
@dataclass
class PanelVerdict:
    crit_rate: float
    crit_dmg: float
    speed: float
    main_stat: str          # 主属性（生命/攻击/防御）
    items: list[tuple[str, str, str]]   # (指标, 实际值, 评价: 优/良/一般/偏低)
    weakest: list[str]      # 短板列表（最多 3 条）
    summary: str            # 一句诊断

def evaluate(character: Character) -> PanelVerdict: ...
```

达标线（按命途分档，写常量，允许后续调）：

| 指标 | 输出型（毁灭/巡猎/智识） | 辅助型（同谐/丰饶/存护/虚无） |
|---|---|---|
| 暴击率 | ≥ 70% 优 / ≥ 55% 良 / < 40% 偏低 | 不评 |
| 暴击伤害 | ≥ 140% 优 / ≥ 110% 良 / < 90% 偏低 | 不评 |
| 速度 | ≥ 134 优 / ≥ 120 良 / < 100 偏低 | ≥ 160 优 / ≥ 145 良 |
| 主属性（攻击%） | ≥ 3000 攻击 优 | 不评 |

诊断文案规则（模板化，不接 AI）：

- 遗器评分低于 60 的件数 ≥ 3 → 「遗器整体欠打磨，优先换掉评分最低的 N 件」
- 主词条错的部位 → 「躯干/脚部主词条不对，收益损失明显」
- 暴击率不足且暴伤很高 → 「暴击率偏低，暴伤收益打折，建议先补暴击」
- 速度未达标且是辅助 → 「速度不达标，回合数吃不满」
- 全部达标 → 「面板健康，可以考虑刷更好的副词条」
