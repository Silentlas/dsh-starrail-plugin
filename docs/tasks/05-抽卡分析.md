# T5 · 抽卡分析

> 负责人：**D** ｜ 前置：T1（出图可选依赖 T2） ｜ 工期：3 天
> 本模块**不依赖 Cookie / 不依赖扫码**，只吃用户自己粘贴的抽卡记录链接。这是整条链路里最独立、最不容易被风控卡住的一块。

## 一、目标

1. 用户粘贴米游社「抽卡记录」链接 → 解析出 `authkey` + `uid`
2. 分页拉全量记录 → 落本地库（增量去重）
3. 输出统计：总抽数、五星/四星数量、平均出金、保底距满、50-50 成败
4. 导出 UIGF / SRGF JSON

## 二、接口与参数（UIGF 生态标准）

```
GET https://api-takumi.mihoyo.com/common/gacha_record/api/getGachaLog
    ?authkey=<urlencode 后的 authkey>
    &authkey_ver=1
    &sign_type=2
    &game_biz=hkrpg_cn
    &lang=zh-cn
    &region=prod_gf_cn
    &gacha_type=<2001|3001|...>
    &size=20
    &end_id=<上一页最后一条 id>      # 翻页用
```

卡池 `gacha_type`：

| 值 | 卡池 |
|---|---|
| 1 | 常驻跃迁 |
| 2 | 新手跃迁 |
| 11 | 角色活动跃迁（角色池） |
| 12 | 光锥活动跃迁（光锥池） |
| 21 | 角色联动跃迁 |
| 22 | 光锥联动跃迁 |

返回 `data.list[]`：`uid` `gacha_type` `item_id` `count` `time` `name` `lang` `item_type` `rank_type` `id`

```
https://webstatic.mihoyo.com/hkrpg/event/e20211215gacha-v2/index.html#/record?authkey=xxxxx&lang=zh-cn
https://act.mihoyo.com/.../gacha_record?...&authkey=xxxxx
```

```python
def parse_link(link: str) -> tuple[str, str]:
    """
    返回 (authkey, uid)，uid 可能为空串
    链接里的 authkey 往往是二次编码的，要 unquote 一次

```

要求：

- 兼容 `#/` 形式的 hash 路由链接（`urlparse` 拿不到 `#` 后面的参数，必须手动截取 `#` 之后的部分）
- 校验 `authkey` 长度（通常 > 200 字符）和字符集，不合规直接给人话提示
- **日志里只打 authkey 长度**，绝不打原值（authkey 等价于凭证）

## 五、`fetcher.py`

```python
"""抽卡记录拉取：分页 + 增量去重"""
from ..utils.store import get_store

PAGE_SIZE = 20
MAX_PAGES = 200   # 防止死循环，200 页 = 4000 条，足够的单池深度

def fetch_all(authkey: str, uid: str, region: str, gacha_types: tuple[str, ...]) -> dict[str, int]:
    """拉取全部记录并写入 gacha_record 表，返回 {卡池: 新增条数}"""
```

要点：

- **翻页靠 `end_id`**，不是页码；某页返回空 `list` 就停
- 每条唯一键是官方返回的 `id`（`gacha_record.id` 已是 PRIMARY KEY，直接 `INSERT OR IGNORE`）
- 支持**增量**：第一次拉全量，之后按「已存在的最大 time」往回只拉新增（实质仍是从头分页，但命中已有 id 后可提前停）
- 429/10001（authkey 失效）要区分：`authkey` 过期提示「链接失效，请回米游社重新复制」
- 请求间隔 ≥ 1.5 秒（与 `core/api/config.py` 的 `REQUEST_INTERVAL` 保持一致），别把接口打崩

## 六、`stats.py`（纯函数，必须可单测）

```python
"""抽卡统计：纯函数，输入记录列表，输出统计结果"""
from dataclasses import dataclass, field

@dataclass
class PoolStats:
    pool: str              # 中文池名
    total: int             # 总抽数
    rank5: int             # 五星数
    rank4: int             # 四星数
    avg_rank5: float       # 平均出金抽数
    current_pity: int      # 当前垫抽（距上次五星）
    hard_pity: int         # 硬保底（角色池 90 / 光锥池 80 / 常驻 90）
    luck: str              # 欧/正常/非，按平均出金与硬保底比值分档
    win_5050: int          # 50-50 胜
    lose_5050: int         # 50-50 负

def analyze(records: list[dict]) -> list[PoolStats]: ...
```

保底常量放 `config.py`：

```python
HARD_PITY = {"角色": 90, "光锥": 80, "常驻": 90, "新手": 50}
```

分档：平均出金 ≤ 60 欧、60~75 正常、> 75 非（**注明是经验分档，不是官方概率**）。

50-50 判定：角色池出现非「当期 UP」五星记一次失败。UP 名单本期**手工维护在 `config.py` 的 `UP_ROLES` 里**，缺省不做 50-50 判定并说明（不要瞎猜）。

## 十一、风险

- authkey 有效期约 24 小时，**必须在文案里写明**，否则用户会一直抱怨「链接失效」
- 官方接口对抽卡链接有频率限制，连续拉 6 个池子要注意间隔，别一次性并发
- UP 角色名单会随版本变，做成常量 + 注释「新版本需更新」，不要试图自动抓（没有稳定来源）
