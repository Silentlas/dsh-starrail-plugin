> 这是**唯一没有旁路**的模块：体力是实时数据，只能打官方接口。它是全项目唯一可能攻克不了的部分，所以安排独立负责人、独立排期，成与不成都不阻塞其他模块。

## 一、目标

1. 让 `#星铁体力` 真正返回数据（现在恒为 `10041`）
2. 补 `#星铁月历`（开拓月历，需要 `cookie_token`）
3. 把「Cookie 绑定」做成可靠路径（含有效性校验、失效提示、巡检）

## 二、当前已知事实（别重复排查）

| 场景 | 结果 |
|---|---|
| `note` + 真 Cookie | `10041`（message 为空） |
| `index` + 真 Cookie | `10041` |
| `widget`（`hkrpg/aapi/widget`）+ 真 Cookie | `10001 Please login` |
| 伪造 uid | `10102 Data is not public` |
| 无 Cookie / 假 Cookie | `10001 Please login` |
| 签名错 | `-10001 invalid request` |
| `getUserGameRolesByCookie` | `0 OK`（Cookie 本身有效） |

已排除：签名、参数形态、设备头、Cookie 字段名、战绩公开开关、`client_type` / `app_version` 组合。
扫码拿到的 v2 凭证**没有 `cookie_token`、没有 `stoken`**——这是重点怀疑方向。

## 三、任务分解

### 3.1 首要验证（半天）

用**浏览器 Cookie**（用户在 `bbs.miyoushe.com` 登录后复制的整行）做一次 `note` 调用：

- 如果成功 → 结论：问题在扫码 v2 凭证缺权限；把「Cookie 绑定」定为主路径，扫码降级
- 如果仍 `10041` → 继续 3.2

**注意**：Cookie 只能在私聊里接收，日志只打长度与前 6 位。验证脚本 `scripts/probe_note_ck.py`，读环境变量 `SR_CK`，不要写进仓库。

### 3.2 三个对照方向（各半天）

| 方向 | 做法 | 判断依据 |
|---|---|---|
| A. Cookie 字段补全 | 用 `stoken` 通过 `getCookieAccountInfoBySToken` 换真 `cookie_token`，拼进 Cookie 再打 note | 若返回 0，说明缺 `cookie_token` 就是根因 |
| B. widget 端点 | 对齐 `nonebot-plugin-mystool`：`/hkrpg/aapi/widget` + `client_type=2` + 带 `cookie_token` | 返回 0 → 换端点即可解决 |
| C. 请求头对齐社区实现 | 补 `x-rpc-app_version` / `x-rpc-client_type` / `x-rpc-device_fp` / `x-rpc-game_biz` 全套，逐个变量单独测（一次只改一个） | 定位到具体缺哪个头 |

做 A/B/C 时**必须一次只改一个变量**，并把结果写成表格 append 到本文件末尾的「排查记录」，否则又变成十来组对照实验互相干扰。

### 3.3 月历（`#星铁月历`）

```
GET https://api-takumi.mihoyo.com/event/srledger/month_info
```

需要 `cookie_token`（v2 不够）。字段：当月星琼收入/支出、各项构成。返回结构以 UIGF 文档为准，不凭记忆写。
